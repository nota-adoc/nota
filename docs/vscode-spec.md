# Nota VS Code Extension — Technical Specification

The visual AsciiDoc editor of Nota as a VS Code extension (`nota-adoc.nota-vscode`; it is not published to npm or the Marketplace).
A `.adoc` or `.asciidoc` file opens in the editor **Nota: Visual editor**: paragraphs, headings, marks (bold, italic,
monospace, strikethrough, highlight), links, coloured text, lists, admonitions, collapsible blocks, code blocks and captions of pictures are edited on the page; what the editor does not read is an island
with its source in it. The text of the VS Code document is the truth: saving, undo, a text editor beside it and changes on
disk work as they do for the built-in editor. The extension needs no network.

- Two modes in one tab: **Visual** and **Text** (the AsciiDoc source with highlighting and line numbers). The button «Text» / «Visual»
  in the title of the tab (or the command «Nota: Text ⇄ Visual») switches; the cursor, the place on the page and the undo history are shared
  by the modes and by VS Code. The mode is not remembered: a file opens visually.
- Optional page metadata header (for example, in files exported from Confluence): a block comment `////` with lines `key: value` at the start of the file, with the attribute entries up to the first block of content, is not drawn as islands. A round badge «i» stands at the top right of the page instead: hovering it for 0.4 s or a click (Enter on the focused badge) opens a card with the path (`ancestors`), the title, the version, the date (`updated_at`, in the language of the plugin) and «Open in Confluence» (only `http(s)`, through `openLink`); Esc, a click elsewhere or a second click close it. «Edit header» in the card opens the lines as islands in place (the cursor on `version:`), «Collapse» or Esc puts the badge back. The file is not touched; Ctrl+A and Delete leave the header. A file without such a block keeps its islands. The attribute entries after the paragraph that is one link («Open in Confluence», which stays a paragraph of the page) are kept out of sight too, up to the first block of content, and the card lists all the hidden attributes under «Page settings»; a line `toc::[]` with nothing else on it is a narrow, read-only line «Table of contents» (Ctrl+A and Delete leave it inside that zone; outside it is selected and deleted as a block); Enter at the end of the link paragraph puts the new paragraph after the last attribute.
- Anchors: the lines `[[id]]`, `[#id]`, `[id=…]` over a heading, a paragraph or an admonition are hidden in «Visual» (the file keeps them byte for byte, links to the section work); the setting `nota.showAnchors` (false by default; an open tab follows it at once) shows each as a one-line plate `# id…` with the whole id in a tip on hover. In «Text» the line is always seen. Other service lines (`.Title`, `[role]`, `[#id.role]`) stay grey and wrap; a long unbreakable line wraps inside its block.
- The look «Sheet»: the text stands on the background of the editor in a page of clamp(38rem, 85% of the tab, 100% of the tab) in the middle (the percent is the setting `nota.pageWidth`, 50–100, 85 by default; an open tab follows it at once, and from 761 px at least 80 px stay at each side for the handles; all blocks share the edges; the width is set by the variables `--nota-page-*` in `style.css`), three capsules and a round one hang over it («Sections» with the name of the current section, the tools, «Remarks», and the round «Nota settings» with a gear, right of «Remarks»; it opens the Settings of VS Code with the settings of Nota only, `@ext:<id>`, in «Visual», in «Text» and in the strip of a big file; the same is the command «Nota: Settings» of the palette, offered in the tab of Nota only; in a tab of 450 px and less the capsule of tools gives up the list buttons, «+» has them), and what opens hangs from its capsule as a card. «Sections»: the setting `nota.outlineView` is `capsule` (the default: the strokes at the edge and the capsule «Sections» as above) or `side`, turned on in the settings or by the command «Nota: Toggle outline view». In `side` the outline is a column to the left of the text, always in sight (240 px wide, 14 px from the edge; the page stands 334 px from the left edge and is narrowed only as far as the column needs, 38rem at least): the current section is lit, a click goes to the title, an arrow at a section with subsections folds them (kept while the tab is open), the rows can be moved as in the panel. It is there while the tab is at least 1022 px wide; in a narrower one the outline is as in `capsule`. A document without section headings shows no outline at all in either view (no column, strokes or capsule «Sections»); the page and the other capsules stay where they are, and the outline appears with the first heading. The command «Nota: Toggle outline view» switches the setting (every open tab follows at once). The view `capsule` is what is described next: the sections and discrete headings, a click goes to the title; in a tab wider than 760 px the capsule «Sections» is gone and a narrow island of strokes at the left edge, in the middle of the tab's height, takes its place: hovering it (150 ms) grows it into the same card as a panel, a click pins the panel (Esc, a click elsewhere or a second click close it). In a tight tab the row shrinks by steps (the capsule «● N remarks» never lies on the tools): at 800 px «Sections» become the icon, at 720 px the remarks become «● N». In a narrow tab (650 px and less) the row is a round «Sections», a stretched capsule of tools (one line, as in a wide tab) and «● N».
  The remarks of Nota (errors and warnings) are underlined in the text, counted in the capsule and in the card «Sections», shown one by one in a card under «Remarks» and listed in the panel «Problems» while a tab of the file is open. In «Text» the capsules stay, the tools and «Sections» are off, «Remarks» bring the tab back to «Visual».
  The fonts are three CSS variables at the top of `style.css`: `--nota-font-text`, `--nota-font-heading`, `--nota-font-ui` (by default the font of VS Code, `--vscode-font-family`; text 15 px, headings weight 600).
- A file over 1 000 000 bytes opens in the mode «Text» with a strip «The file is larger than 1 MB…» and the button «Open visually anyway».
- If the tab fails to open (an error, or no answer in 10 seconds), a screen «The visual editor did not open» says so and offers the text editor. A failure in a tab that
  has shown its document shows the document again with a strip.
- «Reopen Editor With…» switches between **Nota: Visual editor** and the text editor.
- Formatting: the capsule of tools has the style of the paragraph «Text ⌄» and the lists, and the blocks: in a wide tab it is always open, with the icons of the headings 2–6 and of the table, code, Mermaid, admonition, collapsible block and picture; in a narrow one it has «+», which opens the list of all the blocks; the setting `nota.blocksInCapsule` (`all` by default, `frequent`) says which blocks the open capsule shows: all of them, or only the frequent ones (the table, code, admonition and picture, and the lists), with «+» in it and the rest under «+» and in «/»; the marks (B, I, code, S, highlight), «Text color ⌄», «Fill ⌄» and the link are on the panel over the selected text, once, not in the capsule. Alt+F10 (⌥F10 on a Mac) from the text puts the focus on the panel (with no selection, on the capsule); the arrows, Home and End go through its buttons, Esc brings the focus back to the text.
  The colours are a row of circles in place of the buttons of the panel (and of the row «Table» for the fill of cells); it shows the name of the circle under the mouse or the keys (in a block of one width, so nothing moves; «Mixed» for cells of different fills; in a narrow tab the name stands in place of the label). With the cursor in a table a second row «Table» opens under the tools (ten commands; «Cell fill ⌄» fills the whole cell with the label `[.cell-blue]##{empty}##` at the start of its text; drag the mouse across cells or Shift-click to select a block, then it fills several cells in one step). Two cells or more selected (by dragging, Shift-click or the grips) bring the capsule of cells next to the selection, of the shape of the one over selected text: «Merge cells», «Split cells» (with a merged cell), «Alignment ⌄», «Cell fill ⌄», «First row is the header» (when the selection takes the first row), «Clear cells» and «Delete rows/columns: N»; it stands under the selection, over it where there is no room, and folds into «⋯» in a narrow tab; Alt+F10 leads to it. The style of the paragraph, the language of code and the type of an admonition are one drop-down (keys: arrows, Home, End, PageUp/PageDown, first letters, Enter, Esc). Short animations; none with «Reduce motion». A link is put on an address, on a section of the document or on another `.adoc` file of the workspace (`xref:../path/file.adoc[text]`).
  `⌘`-click (`Ctrl`-click off a Mac) on a link in «Visual» opens an address in the browser (VS Code asks as it always does) and a file in a tab; a link to a section
  scrolls to it. In «Text» the panel is off.
- Lists: three buttons in the panel (bulleted, numbered, checklist). Tab and Shift+Tab change the level of an item, Enter makes a new item (in an empty last one it ends the list),
  Backspace at the start joins an item to the one before; `* `, `- `, `. `, `1. ` typed in an empty paragraph start a list; a click on the box of a checklist flips it.
- Admonitions (`NOTE:` and `[NOTE]` over `====`) are boxes with the colour and the icon of their type; the label of the block («Note») is the button of its type: a press (or Alt+F10 from the text) opens a row of the five types in the frame of the block, the choice changes the word in the file only; no hint of the browser, the row does not cover the neighbours of the block.
  A `[%collapsible]` block opens and closes by a click on its title without changing the file; the text inside is edited as usual. Every edit is one step of Cmd+Z.
- Code, pictures, islands: a listing (`----`, `[source,js]`) is a dark block with colours and the word of the language in the corner (a list
  changes it; only `[source,…]` is written); Tab puts two blanks, Shift+Tab takes up to two away. A block image `image::path[]` is drawn from the file next to the document
  (`:imagesdir:` is read; the page's CSP allows `img-src ${cspSource}` and no more), its `.Title` is a caption edited as text; a missing file is the plate «No file {path}», an address
  from the network is «An image from the network is not shown» and is never requested. What the editor does not read (`include::`, a definition list, `....`, `////`, a list with `+`, `:name: value`)
  is an island: its source, edited as text; text that would change the blocks around it stays on the screen marked «Not saved: this text changes the blocks around it» and is not written.
  «/» in an empty paragraph opens the menu «Insert a block» (14 blocks); the capsule has the same 14 blocks: the icons and the three buttons of the lists in a wide tab, «+» with the list in a narrow one; they go in from any place of the cursor (a heading, a list, `NOTE:` and a collapsible block go after the block that holds the cursor, on the screen only until the first letter): the capsule (with `frequent`, «+», «Text ⌄», the lists and four icons) is open when it fits on one line (the width of its invisible copy measured against the room between the side capsules; a tab of 650 px and less is always narrow), else it has «+» with the list under it; the icons are one stop of Tab (←/→, Home and End go through them, Esc goes back to the text); everything is off in «Text». A heading, a list, `NOTE:` and a collapsible block are written
  with the first letter, not before; a table is `|===` 3×3 with a header.
- Tables: a table is a grid of cells (`<table>`) with its head, merged cells and tables in cells down to four levels (`!===`, `,===`, `:===`);
  the text of a cell is edited in place (plain `psv` cells and `a`-cell paragraphs/lists support inline marks and links; other cell styles and formats such as `csv`/`dsv` edit their source as text; Enter does nothing in plain cells). A panel of nine buttons over the table: add a row, add a column,
  delete a row, delete a column, merge, split, head, put a table in the cell, delete the table; over a nested table it says «level N» and the last button deletes that table.
  Drag the mouse across cells (or Shift+click on a second cell) to select a block with a frame around it; Esc, a click or a typed character let it go; the selection is not written to the file. «Merge cells» merges the block. Tab and Shift+Tab go from cell to cell, Tab in the last cell adds a row. Every command is one operation of Nota and one step of Cmd+Z that gives the file back byte for byte;
  a refusal (the last row or column, a merged cell in the way, more than four levels, a cell with a table already) is a strip with the reason in the language of the tab and changes nothing. A table the operations cannot write back
  (a repeat `2*|x`, for one) stays an island. A table whose head is implicit (a blank line after the first row, no `%header`) takes no new row or column or table in a cell: the strip gives the general refusal «This can only be edited in Text mode for now.».
- Moving and the handle of a block: a section is moved by dragging its row in «Sections» (a line above or under the row shows the place; the subsections go with it) or by Alt+↑ and Alt+↓ on the item (a swap with the neighbour of the same level); in «Text» neither works. In «Visual» a handle «⋯» appears at the left of a block under the mouse, 8 px away from the block: a menu with «Caption…» (the line `.Caption`), «Anchor…» (the line `[[id]]`) and «Delete block»; dragging the handle moves the block to another place. Every action is one edit of the file and one step of Cmd+Z; a place the engine refuses is a strip «The block can't be moved here» and changes nothing.
- Diagrams and paste: a block `[mermaid]` over `....` or `----` is drawn as a picture by the library `mermaid`; the code is edited beside it, and the picture is drawn again 0.3 s after the last key. A diagram that does not parse keeps the last good picture, greyed, with the error under it. The library is a separate file `dist/mermaid.js` (about 3.3 MB), loaded when the first diagram is shown, in strict mode, with no network. «/» and «Insert» have «Mermaid»; the sample the block puts in is a small flowchart in the language of the tab. Cmd+V of a page, Word or Google Docs becomes AsciiDoc in one step of Cmd+Z; Cmd+Shift+V pastes plain text.
  Licenses of what `mermaid` brings into the bundle (the tree of `dependencies` of `mermaid` 11.17.2, 104 packages): MIT (66), ISC (32), BSD-3-Clause (3: `d3-ease`, `rw`, `d3-sankey`), Unlicense (`robust-predicates`), Apache-2.0 (`@chevrotain/types`), `dompurify` (MPL-2.0 OR Apache-2.0, taken under Apache-2.0), `khroma` (MIT, in its LICENSE file).
  CSP: `'unsafe-inline'` in `style-src` is accepted as unavoidable for `mermaid` (its `<style>` and the `style` attributes in the SVG); `script-src` stays on a nonce only, and no directive names an external web address: `style-src` and `img-src` carry `cspSource` (the source VS Code gives the webview for its own resources), and nothing else.
- The language is the setting `nota.language`: `auto` (the default: as VS Code, Russian for a language code that starts with `ru`, English for any other), `ru` or `en`. The remarks of «Problems» change at once, an open tab after it is closed and opened again. The names of the commands, of the editor and of the settings in the manifest follow the display language of VS Code (with the Russian language pack they are Russian), not the setting `nota.language`. The Russian version of this file is `README.ru.md`.
- Styles: `⌘⌥0` plain text, `⌘⌥2` and `⌘⌥3` heading 2 and 3 (`Ctrl+Alt+…` elsewhere); the same key again goes back to plain text; a selection takes all its paragraphs and headings in one step; they are also written in the list «Text ⌄» and in the menu «/». On a Mac the keys are commands of the extension (`Nota: Normal text`, `Nota: Heading 2`, `Nota: Heading 3`) in the tab of Nota only, so `⌘⌥0` still switches the layout of the editors elsewhere; in «Text» they do nothing.
- Marks: `⌘B` bold, `⌘I` italic, `⌘E` monospace, `⇧⌘X` strikethrough, `⇧⌘H` highlight (`Ctrl` elsewhere).

## Installation

Nota is a single file, `nota-vscode-0.1.0.vsix`. It is not on the Marketplace: the file is sent to you (or you build it, see «For developers»).
VS Code 1.90 or newer is needed. The extension needs no internet.

**Install.**

1. Open VS Code → Extensions (Cmd+Shift+X on a Mac, Ctrl+Shift+X on Windows and Linux).
2. At the top of the panel press «⋯» (Views and More Actions) → **Install from VSIX…**.
3. Pick the file `nota-vscode-0.1.0.vsix`.
4. Press **Reload Window** in the notification at the bottom right. If the notification is gone, press Cmd+Shift+P (Ctrl+Shift+P) and run «Developer: Reload Window».

**How to check that it is installed.** In Extensions → Installed there is a card «Nota»: publisher `nota-adoc`, version 0.1.0, the description
«Visual AsciiDoc editor for .adoc files in VS Code» (in a Russian VS Code with the language pack, in Russian). Open any `.adoc` file:
the tab is called «Nota: Visual editor», three capsules are over the page («Sections», the tools, «Remarks») and the button «Text» is in the title at the right.
A file to try is `quality/fixtures/editor/visual.adoc` in the Nota repository (File → Open Folder…).

**Update.** Install the new `.vsix` the same way, with «Install from VSIX…», over the old one, then reload the window. If the old version stays
after that (it happens with a file of the same version), uninstall the extension first (below), reload the window and install the file again.

**Uninstall.** Extensions → the card «Nota» → Uninstall → Reload Window. `.adoc` files open in the plain text editor again. The extension does not touch your documents.

**Open `.adoc` as text by default.** The extension has no setting of its own for this; the VS Code setting does it: right-click the tab of an
`.adoc` file → Open With… → Configure Default Editor for "*.adoc"… → Text Editor. The next `.adoc` files open as text. To come back, choose «Nota: Visual editor» the same way.
To open one file as text once: Open With… → Text Editor, or the button «Text» in the tab of Nota itself.

**If something is wrong.**

- An `.adoc` opened as text: the extension is not installed or the window was not reloaded (check the card «Nota»), or the text editor is set as the default above — choose «Nota: Visual editor» the same way.
- The screen «The visual editor did not open» instead of the editor: press «Open in the text editor» — the file is not harmed; then Reload Window and open the file again. If it repeats, send the text of the reason from the screen.
- A file over 1 MB opens at once in «Text»; the button «Open visually anyway» opens it visually.
- There is no «Install from VSIX…» in Extensions: check that the Extensions panel is open and that «⋯» is pressed in its top row.

### For developers

```sh
npm ci
npm run vsix          # packages/vscode/nota-vscode-0.1.0.vsix (dist/, package.json, package.nls*.json, README)
npm run test:vsix     # the contents of the .vsix and its installation into a clean VS Code (temporary --user-data-dir and --extensions-dir)
npm run test:vscode   # e2e in a real VS Code with the extension from the development folder
code --install-extension packages/vscode/nota-vscode-0.1.0.vsix --force
code --list-extensions --show-versions
code --uninstall-extension nota-adoc.nota-vscode
```

`NOTA_VSCODE_PATH=<the executable of VS Code>` takes an installed VS Code instead of the one downloaded to `.vscode-test/`. More in `CONTRIBUTING.md`, the section «VS Code extension». The words of the extension are in two languages: see the section «Localization» there.

## Layout

- `src/host/` — the extension: `provider.ts` (the custom editor, the versions, the messages), `html.ts` (the page, its CSP and the screen «The visual editor did not open»), `extension.ts`.
- `src/webview/` — the tab: `mirror.ts` (the session that mirrors the document), `main.ts` (the two editors, the modes, keys, theme, Cmd+click), `format.tsx` (the panel, the panel over the selection and the windows of `@nota-adoc/react`), `outline.ts` (the tree of sections), `diagnostics.ts` (the texts of the remarks), `style.css`.
- `src/strings.ts` — the strings of the extension in English and Russian; `package.nls.json` and `package.nls.ru.json` — the titles of the commands and the descriptions of the settings.
- `src/protocol.ts` — the messages between them.
- `test/` — tests of the host (a stand-in for `vscode`) and of the tab (jsdom); `e2e/` — the suite for a real VS Code.
